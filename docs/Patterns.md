# Design Patterns & Coding Standards: Lumina's Regret

**Standard Authority**: Effective Java (3rd Edition by Joshua Bloch) & Clean Code Architecture  
**Language Scope**: Pure Java SE 21 (Modern JDK Standards)  
**Performance Focus**: JVM Zero-Allocation Hot Paths & Garbage Collection Minimization

## 1. Effective Java (3rd Edition) Idioms

The following items from Joshua Bloch's *Effective Java* are established as core architectural requirements:

### Item 6: Avoid Creating Unnecessary Objects
- **Hot-Path Collision**: Never instantiate `new Rectangle(...)` inside `CollisionChecker.java` or `GamePanel.update()`. Instead, use primitive integers passed directly to static algebraic methods (`CollisionMath.intersects(...)`).
- **Random Number Generation**: Prohibit `new Random()` inside entity update ticks. Employ `java.util.concurrent.ThreadLocalRandom.current()` to eliminate heap allocation and prevent multithreaded seed contention.

### Item 9: Prefer Try-with-Resources to Try-Finally
- File input streams, native image loaders, font streams, and audio inputs must be wrapped in `try-with-resources`:
  ```java
  // Idiomatic Resource Loading
  try (InputStream is = getClass().getResourceAsStream(path)) {
      if (is != null) {
          image = ImageIO.read(is);
      }
  } catch (IOException e) {
      System.err.println("Failed to load resource: " + path);
  }
  ```
- Guarantees immediate reclamation of OS file handles and prevents descriptor leaks.

### Item 14: Consider Implementing Comparable
- When prioritizing nodes in algorithmic search structures (such as `ai.Node` in the $A^*$ PathFinder), implement `Comparable<Node>` explicitly.
- Maintain consistency between `compareTo()` and `equals()`:
  ```java
  @Override
  public int compareTo(Node other) {
      int cmp = Integer.compare(this.fCost, other.fCost);
      if (cmp == 0) {
          return Integer.compare(this.hCost, other.hCost); // Tie-breaker
      }
      return cmp;
  }
  ```

### Item 15 & 16: Minimize Mutability & Encapsulate Members
- Avoid exposing public mutable fields across subsystems.
- All structural boundaries and state snapshots should favor encapsulation or Java 21 `record` types.

### Item 17: Minimize Mutability (Immutability by Default)
- Immutable state holders (such as `EventRect`, bounding coordinates, and configuration constants) cannot be mutated accidentally across frame ticks, ensuring thread safety and thread-local caching benefits.

### Item 18: Favor Composition over Inheritance
- Traditional game designs often abuse inheritance by making non-actor items (chests, potions, weapons, particles) inherit from a 1000-line `Entity` class.
- The engine architecture is actively decoupling components so that world objects *contain* components (such as an `Inventory` or `Hitbox`) rather than subclassing `Entity`.

### Item 23: Prefer Class Hierarchies / Enums to Tagged Classes
- Tagged integer constants (e.g. `type_player = 0`, `type_npc = 1`, `type_monster = 2`, `type_sword = 3`) are replaced with typed Java `enum` structures (such as `quest.QuestType`) and sealed interfaces for domain modeling.

### Item 78: Synchronize Access to Shared Mutable Data
- Hardware input states generated by the AWT Event Dispatch Thread (EDT) and consumed by `gameThread` must use atomic or volatile memory barriers to guarantee the *happens-before* relationship (JSR-133).

## 2. Core Architectural & Behavioral Design Patterns

### 2.1 State Pattern (`gp.gameState` & `quest.QuestType`)
The engine structures high-level operational modes using finite state machines:
- **Engine State**: Managed in `GamePanel.java`. Distinguishes rendering, input processing, and entity simulation across states (`playState`, `dialogueState`, `tradeState`, `gameClearState`).
- **Narrative Quest State**: Managed in `QuestManager.java`. Decouples dialog text, map gates, and boss availability from hardcoded entity logic.

### 2.2 Strategy Pattern (Path Following & Combat Logic)
Movement and decision-making algorithms are isolated from entity state:
- Static entities execute proximity checks.
- Roaming NPCs utilize randomized step counters.
- Targeted actors (monsters and guided NPCs) execute $A^*$ search trajectories using `PathFinder.search(startCol, startRow, goalCol, goalRow)`.

### 2.3 Min-Heap Priority Queue Pattern ($A^*$ Optimization)
The pathfinder replaces linear $O(N)$ list sweeps with a binary min-heap priority queue:

```
                  ┌───────────────┐
                  │ PriorityQueue │
                  │  (Min-Heap)   │
                  └───────┬───────┘
                          │ O(log N) insert & poll
                          ▼
            [Node: F=12, H=4] ◄── Top Priority
            /               \
   [Node: F=14, H=6]    [Node: F=15, H=5]
```

- Traversal time is reduced from $O(V^2)$ to $O(E \log V)$.
- Eliminates 1.3 million unnecessary loop iterations per second across pathfinding actors.

### 2.4 Event-Driven Proximity Observer (Interaction Engine)
Interactions do not rely on fragile 3-pixel collision projections. Instead, `Player.java` runs a radial Euclidean observer:

$$r = \sqrt{(x_{\text{player}} - x_{\text{target}})^2 + (y_{\text{player}} - y_{\text{target}})^2}$$

- Any interactable within $r \le 76 \text{ px}$ (1.6 tiles) is highlighted by a floating UI badge.
- Inputs (`E`, `ENTER`, or mouse click) instantly trigger the context-appropriate interaction (`speak()`, `openChest()`, `unlockDoor()`, or `cutTree()`).

## 3. Hot-Path Zero-Allocation Paradigms

```
┌────────────────────────────────────────────────────────────────────────┐
│                        60 HZ HOT PATH RULES                            │
├────────────────────────────────────────────────────────────────────────┤
│ ❌ PROHIBITED INSIDE update() & draw():                                │
│   • new Rectangle(...)                                                 │
│   • new ArrayList(...)                                                 │
│   • new Random(...)                                                    │
│   • string1 + " " + string2 (String concatenation in loops)            │
│   • rawText.split(...) inside render loops                             │
│                                                                        │
│ ✔ MANDATED:                                                            │
│   • CollisionMath.intersects(x1, y1, w1, h1, x2, y2, w2, h2)           │
│   • ThreadLocalRandom.current()                                        │
│   • Cached arrays or pre-allocated collections                         │
│   • UI.wrapDialogueText() executed only when dialogue string updates   │
└────────────────────────────────────────────────────────────────────────┘
```

By adhering to zero allocations in the hot path, JVM Eden generation allocations drop from megabytes per second to near-zero, eliminating micro-stutters and GC frame drops.

## 4. Code Smells & Anti-Pattern Ban List

| Anti-Pattern | Description | Remediation Protocol |
| :--- | :--- | :--- |
| **God Class** | Monolithic classes exceeding 1,000 LOC with dozens of disparate concerns. | Deconstruct into dedicated sub-managers (e.g., `CollisionMath`, `QuestManager`, `MouseHandler`). |
| **Inheritance Abuse** | Subclassing `Entity` for inanimate objects (`OBJ_Key`, `OBJ_Axe`). | Decouple items into dedicated `Item` / `Object` classes; favor composition. |
| **Magic Numbers** | Unexplained coordinates and dimensions scattered in logic. | Centralize constants in `GamePanel` (e.g. `tileSize`, `screenWidth`, `screenHeight`). |
| **Unmanaged I/O Streams** | Calling `getResourceAsStream()` without closing the stream. | Always use `try-with-resources`. |
| **Silent Exception Catching** | Empty `catch (Exception e) {}` blocks. | Log meaningful error telemetry or rethrow as a domain exception. |
